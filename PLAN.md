# The plan this curriculum is written against

Every schedule, phase boundary, and time estimate in the lessons assumes the
parameters below. If yours differ, the material still works — the calendar
around it is what you would change.

| | |
|---|---|
| **Owner** | Harshit Wandhare |
| **Started** | 2026-08-13 |
| **Goal** | Summer 2027 SWE internship, then a full-time offer |
| **Time budget** | 90 minutes/day, 6 days/week, plus one 2-hour weekend block |
| **Language** | Python for interviews, TypeScript for product work |

## Why these numbers

**90 minutes a day, not four hours.** A schedule you can hold for six months
beats one you abandon in three weeks. The [daily protocol](README.md#3-the-daily-90-minute-protocol)
is built to fit inside that window with the review queue included.

**Six days, not seven.** The seventh day is what makes the other six
sustainable.

**Applications run in parallel with studying, from day one.** Internship
hiring is rolling and the windows open in July. Waiting until the curriculum is
finished means applying after the reqs have closed. See
[the timing situation](README.md#0-read-this-first-the-timing-situation).

**Python, decided once.** Revisiting the language choice is the most common way
to lose two weeks. The reasoning is in
[why Python](README.md#1-why-python-decided-once) and it is not reopened.

## Adapting it

If you have more time per day, the phase boundaries move earlier but the order
does not change — the dependencies between topics are real. If you have less,
cut the [phase plan](README.md#4-phase-plan) from the back, not the front: the
first three files carry roughly 40% of what interviews actually ask.

Progress is tracked in [tracker.md](tracker.md).
